# بوت ديسكورد - أنظمة الإدارة والبرودكاست

## 1. تجهيز البوت على Discord Developer Portal
1. روح لـ https://discord.com/developers/applications واعمل تطبيق جديد
2. من تبويب **Bot** فعّل الخيارات التالية تحت "Privileged Gateway Intents":
   - Server Members Intent
   - Message Content Intent
3. انسخ الـ **Token** تبع البوت

## 2. دعوة البوت لسيرفرك
من تبويب **OAuth2 → URL Generator** اختار:
- Scopes: `bot` و `applications.commands`
- Bot Permissions (على الأقل):
  - Manage Roles
  - Ban Members
  - Kick Members
  - Moderate Members (Timeout)
  - Manage Channels
  - Manage Webhooks
  - **View Audit Log** ⚠️ (ضروري لنظام الحماية، بدونها ما بيعرف مين سوى العملية)
  - Send Messages
  - Embed Links
  - Read Message History
    - Direct Messages

⚠️ **مهم جداً**: بعد ما تضيف البوت، لازم تسحب **رتبة البوت لفوق** بترتيب الرتب (Server Settings → Roles)
حتى تكون أعلى من كل الرتب يلي بدك البوت يتحكم فيها (يعطيها/يشيلها/يبندها/يعطيها تايم).
بدون هيك، ديسكورد نفسه بيرفض تنفيذ العملية.

## 3. إعداد البرودكاست

تم دمج ميزة البرودكاست الموجودة في ملف `broadcast_(1)_1786187501781.js`
داخل البوت Python كـ Cog واحد، لذلك لا تحتاج إلى تشغيل بوت Node منفصل.

أضف مفتاحاً ثابتاً اسمه `BC_ENCRYPT_KEY` إلى متغيرات البيئة. يجب أن يكون
سلسلة hex بطول 64 حرفاً، ويمكن توليده مرة واحدة بهذا الأمر:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

يُستخدم المفتاح لتشفير توكنات بوتات البرودكاست قبل حفظها داخل
`data/guilds.json`. لا تغيّر المفتاح بعد حفظ التوكنات.

أوامر البرودكاست:

- `/send-broadcast-panel` → نشر لوحة التحكم (للأدمن).
- `!bc الرسالة` → إرسال للجميع (للأدمن).
- `!obc الرسالة` → إرسال للأعضاء المتصلين فقط (للأدمن).
- `/whitelist-borad @رتبة` → تحديد رتبة إضافية مطلوبة لاستخدام البرودكاست (لِمالك السيرفر فقط).
- زر إضافة التوكن → تسجيل بوت برودكاست وتخزين توكنه مشفراً.
- زر تحديد الرسالة → حفظ الرسالة الحالية.
- زر بدء الإرسال → اختيار الأونلاين أو الأوفلاين أو الجميع.
- `/remove-token` و`/remove-all-tokens` → للمالك فقط.

بعد ضبط whitelist، يجب أن يملك المستخدم **Administrator والرتبة المحددة معاً**؛
صلاحية Administrator وحدها لا تتجاوز whitelist. لتفريغ whitelist استخدم
`/whitelist-borad` بدون اختيار رتبة. لا يمكن اختيار رتبة مساوية أو أعلى من رتبة
البوت، ومالك السيرفر وحده يستطيع تغيير هذا الإعداد.

## 4. تشغيل البوت محلياً
```bash
pip install -r requirements.txt
cp .env.example .env
# افتح .env وحط التوكن تبعك
python main.py
```

## 5. الإعداد الأول داخل السيرفر
بعد ما يشتغل البوت، شغّل هاي الأوامر (سلاش) مرة وحدة بكل سيرفر:

- `/set-up-time` → رتبة معطي التايم، الحد اليومي، رتبة الأدمن، قناة اللوق
- `/set-up-role` → الرتبة المسموحة، قناة اللوق
- `/set-up-ban` → الرتبة المسموحة، الحد اليومي، رتبة باند لا نهائي، قناة اللوق
- `/set-up-security bot-add` → حماية إضافة البوتات (مين مسموح، لوق، رتبة إشعار، رتبة سجن)
- `/set-up-security prune` → حماية Prune (نفس الخيارات)
- `/set-up-security webhook` → حماية الويب هوك (نفس الخيارات)
- `/set-up-security channels` → حماية إنشاء/حذف القنوات (نفس الخيارات)
- `/set-up-security roles` → حماية حذف/تعديل الرتب (نفس الخيارات)
- `/set-up-add-role` → إعداد نظام الترقية (مين مسموح، لوق)
- `/set-up-remove-role` → إعداد نظام التخفيض (مين مسموح، لوق)
- `/set-up-reply` → إعداد نظام الردود التلقائية (الرتبة المفعّلة + بانل 20 خانة رد)
- `/send-broadcast-panel` → نشر لوحة التحكم بالبرودكاست

⚠️ أي نظام حماية ما تسويله `/set-up-security` بيضل معطّل تلقائياً (ما بيتفعل إلا بعد الإعداد).

## 6. الأوامر المتاحة
| الأمر | الوظيفة |
|---|---|
| `$تايم @شخص` | إعطاء تايم أوت (يفتح قائمة مدة + سبب + تأكيد) |
| `$ان @شخص` | إلغاء التايم أوت |
| `$رتب @شخص` | تعديل رتب الشخص (إضافة/إزالة) |
| `$باند @شخص` | باند الشخص (سبب + تأكيد مزدوج) |
| `$ترقية @شخص عدد` | ترقية الشخص N رتبة بسلّم الرتب (ما تقدر توصله لرتبتك أو أعلى) |
| `$تخفيض @شخص عدد` | تخفيض الشخص N رتبة (ما تقدر تخفض حد رتبته أعلى/تساوي رتبتك) |
| `$ق` | تسكير الروم مع إبقائه مخفياً إذا كان مخفياً، ثم إظهار تأكيد `تم تسكير الروم` |
| `$ف` | فتح الكتابة في الروم مع إبقائه مخفياً إذا كان مخفياً، ثم إظهار تأكيد `تم فتح الروم` |

## 7. نظام الحماية (Anti-Nuke)
البوت بيراقب سجل التدقيق (Audit Log) تلقائياً بعد الإعداد، وبيتصرف **فوراً** (رد فعل، مش منع مسبق):

| النوع | شو بيصير لو حد غير مصرح سوى العملية |
|---|---|
| 🤖 إضافة بوت | طرد البوت + شيل رتب الشخص + رتبة سجن |
| 🧹 Prune | شيل رتب الشخص + رتبة سجن |
| 🔗 إنشاء ويب هوك | حذف الويب هوك فوراً + شيل رتب الشخص + رتبة سجن |
| ➕🗑️ إنشاء/حذف قناة | حذف القناة (لو إنشاء) + شيل رتب الشخص + رتبة سجن |
| 🗑️✏️ حذف/تعديل رتبة | شيل رتب الشخص + رتبة سجن |

- صاحب السيرفر والبوت نفسه محصّنين دايماً من كل الأنظمة
- ⚠️ **رتبة البوت لازم تكون أعلى** من أي شخص ممكن يحاول يخرب، وإلا البوت رح يكتشف ويسجل وينبه بس ما رح يقدر يشيل الرتب فعلياً (قيد ديسكورد نفسه)

## 8. ملاحظات تقنية
- التخزين بملف `data/guilds.json` (يتصفّر الحد اليومي حسب التاريخ الفعلي/اليوم الحالي)،
  والكتابة تتم بشكل آمن حتى لا يضيع الملف عند توقف مفاجئ
- كل الأزرار والقوائم مقيّدة على الشخص يلي كتب الأمر بس (ما فيك تتفاعل معها إذا مو إلك)
- في كولداون 10 ثواني بين كل عملية باند
- على استضافة سحابية (Railway وغيرها): لازم تفعّل **Volume** بمسار `/app/data` حتى تضل الإعدادات محفوظة بعد أي Redeploy أو Crash؛
  إعادة تشغيل البوت داخل نفس البيئة تحفظ الإعدادات تلقائياً
